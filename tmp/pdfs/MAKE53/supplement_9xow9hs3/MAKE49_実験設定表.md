## 0. 段階 1 の結果を受けた前提の変更

段階 1 で確定した A1（実効 $\beta = \beta/m$）により、**既存の VAE 実験はすべて再実行が必要**である。
本設定表は「既存結果に新実験を追加する」計画ではなく、**共通規約のもとで主比較を作り直す**計画である。

この変更で失われるもの（方針 §4.5 の予告が現実化した部分）:

- 原稿の $\beta$ の値は文献の $\beta$ と読み替えなしには比較できない。

失われないもの: 手順の設計、ID 推定の安定性の議論、NOLTA2025 との差分整理、理論の限定。

## 1. 事前指定する 6 項目（本設定表の中心）

### 1.1 AU 評価の主方式 → **方式 2（品質確認から独立した予測）を採用**

方針 §5.5「AU 診断の有用性の定義」の 2 案のうち、**方式 2 を主要な AU 評価として一つだけ採用する**。方式 1 は実施しない。

**採用理由**:

1. 同一 checkpoint 群で評価でき、**再学習を要しない**。A1 により全実験を再実行する以上、追加の学習予算を要する方式 1 は主方式にできない。
2. 方式 1（$\beta$ 調整・容量拡張による品質回復）は、A1 の修正前後で $\beta$ の意味が変わるため、介入の解釈が交絡する。
3. 方針自身が方式 2 を推奨としている。

**予測課題の定義**（事前固定）:

| 項目 | 定義 |
|---|---|
| 評価単位 | 1 checkpoint $=$（データセット, アーキテクチャ, $m$, seed, 最良 epoch） |
| 予測対象 $Y$ | **候補グリッド上で 1 つ小さい点 $m^-$ で学習したモデルが $Q$ を満たすか**（二値） |
| 非循環性 | $Y$ は別の $m^-$ で学習した別モデルの品質であり、現 checkpoint の AU から決まらない |
| 実務的意味 | 「まだ縮められるか」という探索上の判断そのもの |
| 基本特徴量 $S_{\text{base}}$ | $D_{\mathrm{val}}(m)$, $\mathrm{KL}_{\mathrm{val}}(m)$, $\mathrm{ELBO}_{\mathrm{val}}(m)$, $m$, $m/\hat d_{\mathrm{ID}}$, 最終 20 epochs の $D_{\mathrm{val}}$ の傾き |
| AU 追加特徴量 $S_{\text{AU}}$ | $S_{\text{base}} \cup \{\mathrm{AU}(m),\ \mathrm{AU}(m)/m,\ \mathrm{AU}(m)/\hat d_{\mathrm{ID}}\}$ |
| 予測器 | ロジスティック回帰（L2）。正則化強度は**開発条件の validation のみ**で選択し、以後固定 |
| 開発条件（当てはめ） | MNIST FC-VAE のみ |
| 評価条件（未使用） | dSprites, Fashion-MNIST, CIFAR-10, MNIST Conv-VAE |
| 指標 | balanced accuracy, AUROC |
| **主要量** | $\Delta\mathrm{AUROC} = \mathrm{AUROC}(S_{\text{AU}}) - \mathrm{AUROC}(S_{\text{base}})$ |

**事前指定した判定規則**:

> 未使用条件全体での平均 $\Delta\mathrm{AUROC}$ について、**seed 単位のブートストラップ（2000 反復）**で 95% 信頼区間を求める。
> 区間の下限が $0$ を上回る場合に限り「AU に診断としての増分価値がある」と判定する。
> 区間が $0$ を含む、または上限が $0$ を下回る場合は、**AU を補助分析へ移し、主要な方法貢献から外す**（方針 §11 の該当行）。

$\delta$ や V1/V2 の係数を動かして「合格」が増えたことは、この判定の証拠に**しない**。

### 1.2 E7a の主要比較時点 → **5 epochs と 300 epochs の 2 点**

| 項目 | 値 |
|---|---|
| **H1 の主要比較** | **(5 epochs, 300 epochs)** |
| 全軌跡の記録 | 1, 2, 5, 50, 300 epochs（同一 checkpoint 系列） |
| 更新回数・経過時間 | 各時点で保存 |

**5 を選ぶ理由**: FONDUE 付録 G が FONDUE-VAR を評価した 1/2/5 epochs のうち**最長**であり、原著の早期設定に最も有利な点である。早期側に不利な点を選んで差を作らない。
**300 を選ぶ理由**: 本論文の既存の長時間条件であり、追加の学習予算を要しない。

**主要統計量と判定**:

> 同一 $m$・同一読み取り方式における**seed 間 SD** を 5 epochs と 300 epochs で比較する。
> seed 単位ブートストラップ（2000 反復）で比 $\mathrm{SD}(300)/\mathrm{SD}(5)$ の 95% 信頼区間を求め、
> **上限が 1 を下回る場合に H1 を支持**とする。

**退化の扱い**: $\mathrm{AU}=0$ または $\mathrm{AU}=m$ の条件は SD が小さくなるため、
値そのものを必ず併記し、**退化している条件を H1 の支持証拠に数えない**。

**「収束」と書かない**。300 epochs は固定の学習長であって収束の同義語ではない。plateau 判定は §5.2 に定義する。

### 1.3 active 数 / active+mixed 数の扱い → **主比較は active + mixed（$= m -$ passive）**

| 読み取り | 定義 | 位置づけ |
|---|---|---|
| **active + mixed** | $m - (\text{passive 数})$ | **H2 の主比較に使う** |
| active のみ | U12 の定義による active 数 | 補助表示。Algorithm 3 の返り値として B6b の再現に使う |
| passive | U12 の定義（データ間分散 $<0.1$ かつ平均 $\in[0.9,1.1]$） | 内訳として常に併記 |

**採用理由**: AU は $\mathrm{Var}_x(\mu_j) > \delta$ により「崩壊していない」ユニットを数える。
FONDUE の変数型では passive（$\sigma^2 \approx 1$, 事後 $=$ 事前）が崩壊ユニットに対応し、
active（$\sigma^2 \approx 0$）と mixed（中間）はいずれも情報を持ちうる。
したがって **AU と推定対象が揃うのは $m - \text{passive} = \text{active} + \text{mixed}$** である。
active 単独と AU を比べると、定義上の被覆範囲の差を安定性の差と取り違える。

3 区分の内訳（active / mixed / passive）は全条件で表に出す。**合計が $m$ に一致することを毎回確認する。**

### 1.4 keep_mixed → **主比較は `keep_mixed = True`**

| 設定 | 値 | 位置づけ |
|---|---|---|
| **主比較** | **`keep_mixed = True`**（返り値 $=$ active + mixed） | B6b の主設定 |
| 感度評価 | `keep_mixed = False`（返り値 $=$ active のみ） | 代表条件（dSprites, MNIST）のみ |

**採用理由**: §1.3 の主推定対象と一致させ、**E7a と E7b が同じ量を測る**ようにする。
付録 G の探索が「passive/mixed が出るまで容量を倍増する」以上、停止時点で「まだ使われている容量」を数える読み方と整合する。

**主張しないこと**: これは Table 7 がどちらの分岐を使ったかについての主張では**ない**。
原著の実験設定・ログから特定できないため、**「未確認」と明記する**（U15）。
本設定は事前に固定した再実装上の選択であって、原著の再現の断定ではない。

**実装**: `keep_mixed` を**独立した Boolean 引数**にする。
原著コードが `cfg.threshold is True / is False` で分岐する経路は使わない（数値 threshold を渡すと正常な終了条件を満たさないため）。

### 1.5 品質許容誤差 → $\epsilon_D$ の確定

**anchor の規則**（事前固定）:

> $m_{\mathrm{anchor}} = $ 候補グリッド $\mathcal{M}$ の**最大点**。
> anchor は候補と**同じモデル種別・同じ likelihood・同じ $\beta$・同じ学習設定**で学習し、その費用を総費用に計上する。
> **参照 AE を VAE の品質基準に流用しない。**

最大点を使うのは、弱い anchor を選んで基準を緩めないためである（方針 §4.2）。

**許容誤差の規則**（事前固定）:

$$\epsilon_D = \max\Bigl(\underbrace{0.10 \cdot D_{\mathrm{anchor}}}_{\text{相対}},\ \underbrace{3 \cdot \mathrm{SD}_{\text{seed}}(D_{\mathrm{anchor}})}_{\text{seed 雑音}},\ \underbrace{10^{-3}\cdot \mathrm{Var}(X_{\mathrm{val}})}_{\text{$D_{\mathrm{anchor}}\approx 0$ 対策}}\Bigr)$$

$$T_D = D_{\mathrm{anchor}} + \epsilon_D, \qquad Q(m): D_{\mathrm{val}}(m) \le T_D$$

- 第 2 項は、許容誤差が**必ず seed 間の実行ばらつきを上回る**ことを保証する。
- 第 3 項は、合成多様体で $D_{\mathrm{anchor}}$ がほぼ 0 になる場合に $\epsilon_D$ が 0 に潰れることを防ぐ（方針 §4.2 の要請）。
- $T_D$ は**同一の比較条件で全方法に共通**とする。$\beta$ 調整や容量拡張の後に anchor を作り直さない。

**感度水準**: 相対 1%, 5%, 25%, 50%（主値 10% を含めて 5 水準）。
方針 §5.5 のとおり、これらは**感度評価の候補であって推奨値として正当化済みのものではない**。

**開発条件での事前計算（現行データ、A1 修正前）**:

MNIST FC-VAE、3 seeds（42, 123, 777）、300 epochs、anchor $m=64$:

| | 値 |
|---|---|
| $D_{\mathrm{anchor}}$ | 0.008938 |
| $\mathrm{SD}_{\text{seed}}$ | 0.000135 |
| $3\,\mathrm{SD}$ | 0.000405（$D_{\mathrm{anchor}}$ の 4.5%） |
| **binding な項** | **相対 10%**（$3\mathrm{SD}$ の 4.5% を上回るため） |
| $T_D$ | 0.009831 |

この $T_D$ で $Q$ を満たす最小の $m$ は **64**（すなわち anchor 自身）である。
感度水準でも 25% まで $m=64$ のままで、50% で初めて $m=20$ になる。

> **事前登録された予測**: A1 修正前のデータをそのまま使う限り、MNIST 開発条件の主水準（10%）は
> `NO_COMPACT_ALTERNATIVE_FOUND` を返す。**この結果が出ても $\epsilon_D$ を緩めない。**

ただし段階 1 の $\beta$ スキャン（A1 修正後）では、$D_{\mathrm{val}}$ が $m$ について**単調でなくなる**条件が観測されている。
修正後の再実行で anchor と $T_D$ を**再計算**し、上記の事前計算は「修正前データに対する参考」として残す。

### 1.6 予算・停止条件

**学習の停止**（全方法・全データ共通）:

| 項目 | 値 |
|---|---|
| 最大 epochs | 300 |
| early stopping | validation 目的関数（VAE: 通常 ELBO / AE: val MSE）が **30 epochs** 連続で最良値を更新しない場合に停止 |
| 採用 checkpoint | validation 目的関数の最良点。**test は一切使わない** |
| plateau 判定（E7a 用） | 直近 **50 epochs** の validation 目的関数の相対変化が **1% 未満**。満たさない場合は「未 plateau」と記録する |

**early stopping を適用しない例外（E7a）**:

E7a は**固定した学習軌跡に沿って読み取りを比較する**実験なので、
early stopping で打ち切ると 300 epochs 時点の checkpoint が存在しなくなり、§1.2 の主要比較（5 vs 300）が成立しない。
したがって **E7a の軌跡ランは early stopping を適用せず、必ず 300 epochs まで回す**。
plateau 判定は記録のみ行い、停止には使わない。

early stopping を適用するのは**選択を伴う実験**（E1, E7b, +Q 対照）である。
両者は同じ学習設定を共有するが、停止規則だけが異なる。この差は結果表に明記する。

**「収束」という語は使わない**。plateau か未 plateau かを記録する。

**探索の予算 $B$**（1 つの（データセット, 方法, seed）あたり）:

| 項目 | 値 |
|---|---|
| 学習ラン数の上限 | **12 ラン**（anchor と再探索を含む、**選択対象のモデル族＝候補 VAE の学習のみを数える**）。参照 AE と probe は実時間にのみ計上する |
| GPU 実時間の上限 | §8 の校正実行で実測して確定し、本表に追記してから実験を開始する |
| 上限に達した場合 | `BUDGET_EXHAUSTED` を返して停止 |

**終了状態**（Algorithm 1 と一致する 4 種 ＋ 段階 4 で追加した 1 種）:

| 状態 | 条件 |
|---|---|
| `SUCCESS` | $Q$ を満たす候補が見つかり、それが anchor でない |
| `NO_COMPACT_ALTERNATIVE_FOUND` | $Q$ を満たすのが anchor のみ |
| `ID_UNRELIABLE` | §5.3 の ID 安定性・推定器一致の基準を満たさない |
| `BUDGET_EXHAUSTED` | 予算内に評価を完了できない |
| `DEGENERATE_SELECTION` | 方法が学習不可能な次元（$m<1$）を返した。**段階 4 で追加**（2026-09-13）。FONDUE-VAR の `keep_mixed=False` が active 数 0 を返す場合に発生する。原著 Algorithm 3 どおりの挙動であり実装の誤りではない。記録し、内訳から落とさない |

> **集計規則**: `BUDGET_EXHAUSTED` で終わった試行を、選択成功率・選択 $m$ の平均から**黙って除外しない**。
> 終了状態の内訳を全方法について必ず表に出す。除外する分析を追加する場合は、除外前の表と併記する。

## 2. A1 を受けた損失規約の確定

**全 VAE 実験で以下に統一する。**

```python
# 再構成項: サンプルあたり、入力次元について和
recon = F.mse_loss(recon_x, x, reduction='sum') / x.size(0)
# KL 項: サンプルあたり、潜在次元について和（バッチのみ平均）
kl    = -0.5 * torch.sum(1 + logvar - mu.pow(2) - logvar.exp()) / x.size(0)
loss  = recon + beta * kl
```

- これにより $\beta$ は文献の $\beta$-VAE と同じ意味になり、**$m$ に依存しない**。
- 原稿に記載する $\beta$ はこの規約の値とし、**旧規約の値との対応表を補足資料に載せる**（旧 $\beta$ は $\beta_{\mathrm{eff}} = \beta/m$ に相当）。
- 単体テスト: $m$ を変えて同一の $(\mu, \log\sigma^2)$ を与え、KL が $m$ に比例して増えることを確認する回帰テストを置く。

## 2.5 $\beta$ の確定（A1 の修正に伴い必須）

規約を直すと $\beta$ の意味が変わるため、**$\beta$ を新規に事前指定する**。

| 項目 | 値 |
|---|---|
| **主設定** | **$\beta = 1$（通常の VAE、ELBO そのもの）** |
| 事前宣言する $\beta$ 梯子 | **0.25, 0.5, 1, 2, 4**（全方法・全データで同じ梯子を使う） |
| 旧 $\beta$ との対応 | 旧実装の $\beta=4$ は $\beta_{\mathrm{eff}} = 4/m$。掃引範囲 $m\in[4,64]$ は $\beta_{\mathrm{eff}}\in[0.0625,\,1.0]$ に相当する |

**$\beta=1$ を主設定にする理由**: $\beta=1$ は VAE 自身の ELBO であり、調整を要さず、文献と直接比較できる。
**AU の挙動を見て $\beta$ を選ばない。** 段階 1 の $\beta$ スキャンで
$\beta=0.25$ が AU $\approx 12 \approx \hat d_{\mathrm{ID}}$ という「都合のよい」作動点になることは確認しているが、
**この理由で $\beta$ を選ぶことはしない**。$\beta$ は梯子全体を因子として回し、各 $\beta$ で $m$ 選択を評価する。

方針 §5.5 E1 のとおり、まず $\beta$ を固定して $m$ 選択の効果を調べ、
次に $\beta$ も validation で選ぶ実験を追加してその費用を含める。

**重要な帰結**: 段階 1 の確認では、修正規約のもとで **AU は $m$ にほとんど依存せず $\beta$ でほぼ決まる**。
このため「$m$ を増やすと AU が飽和する」という観測は、修正後には**そのままの形では再現しない見込み**である。
AU の $m$ 依存性を前提とした本文の記述（V2 の上下係数の議論を含む）は、再実行の結果に応じて書き直す。

## 2.6 likelihood の確定（段階 3 の校正で必要になった）

段階 3 の校正で、**dSprites は Gaussian（MSE）尤度では全 $\beta$ で完全に事後崩壊する**ことが判明した。
尤度診断（`src/make49/stage3_dsprites_likelihood.py`）で原因を切り分けた結果:

| likelihood | $\beta$ | AU | val SSE | val KL |
|---|---|---|---|---|
| Gaussian | 1.00 | 0/16 | 173.52 | 0.000 |
| Gaussian | 0.25 | 0/16 | 173.52 | 0.000 |
| **Bernoulli** | 1.00 | **14/16** | **7.30** | 28.03 |
| **Bernoulli** | 0.25 | **16/16** | **5.91** | 51.65 |

（全ゼロ予測の SSE は 173.50、平均画像予測は 153.88。Gaussian は全ゼロ予測と同等で止まっている）

**データの型に応じて尤度を分ける**:

| データセット | 尤度 | 再構成項 | 理由 |
|---|---|---|---|
| **dSprites** | **Bernoulli（BCE）** | `binary_cross_entropy(reduction='sum') / B` | 二値画像（白画素 4.24%）。FONDUE が依拠する disentanglement_lib 系の標準設定でもあり、公表値との比較可能性が上がる |
| MNIST / Fashion-MNIST | Gaussian（MSE） | `mse_loss(reduction='sum') / B` | 既存実験と同じ。連続値として扱う |
| CIFAR-10 / SVHN | Gaussian（MSE） | 同上 | 連続値 |
| 合成多様体 | Gaussian（MSE） | 同上 | 連続値。標準化後に学習する（A4） |

**必ず守る事項**:

- 使用した尤度を**全方法・全表・全図で明記**する。
- **尤度の異なるデータ間で損失値を直接順位づけしない**（方針 §5.3 の原則）。
- $\beta$ の意味は尤度によって変わる（再構成項のスケールが違う）。
  **$\beta$ 梯子は尤度ごとに別物として扱い、データをまたいで同じ $\beta$ を「同じ強さ」と書かない。**
- 評価指標の**画素平均 MSE は尤度によらず共通**に計算する（§3）。品質条件 $Q$ はこの共通尺度で判定する。
- 同じデータセット内では**全比較法が同じ尤度**を使う。

## 3. 評価指標の規約

| 指標 | 規約 |
|---|---|
| **再構成 MSE** | **画素平均**（`reduction='mean'`）に統一。既存の和形式の表（`E4_results_mnist.json` 等）は再計算する（A6） |
| VAE の再構成 | **決定論的再構成 $g(\mu(x))$** に固定。事後サンプル平均は使わない |
| ELBO | $\beta$ で重みづけた目的関数とは**別に**、通常の ELBO（$\beta=1$）を必ず併記 |
| KL | サンプルあたり、潜在次元について和 |
| 下流評価 | 固定した linear probe の test accuracy。probe の正則化は validation で選択 |
| AU | $\mathrm{Var}_x(\mu_j) > \delta$、$\delta = 10^{-2}$（開発条件で固定）。感度 $\delta \in \{10^{-3}, 10^{-2}, 10^{-1}\}$ |
| 合成データ | **標準化してから学習・評価**する（A4）。$\delta$ は標準化後の潜在分散に対して定義する |

**train MSE も評価モードで計算**し、validation と同じ再構成方式を使う（方針 §5.5 E2）。

## 4. データ分割

| 項目 | 値 |
|---|---|

### 5.1 候補グリッド $\mathcal{M}$

| データセット | グリッド |
|---|---|
| MNIST / Fashion-MNIST | 2, 4, 6, 8, 10, 12, 16, 20, 24, 32, 48, 64 |

探索順序と拡張規則は Algorithm 1 に従う。**全方法で同じグリッドを使い、比較の分母を一致させる。**

### 5.2 初期範囲

| 項目 | 値 |
|---|---|
| 初期係数 $c$ | **2**（検証対象の既定値。第一原理からの導出ではない） |
| 丸め | $c\hat d_{\mathrm{ID}}$ **以上**の最小のグリッド点 |
| AE の初期窓 | $[\hat d_{\mathrm{ID}},\, 2\hat d_{\mathrm{ID}}]$ に含まれるグリッド点 |
| VAE の初期診断点 | $2\hat d_{\mathrm{ID}}$ 以上の最初のグリッド点。**最適点として扱わない** |
| $c$ の感度（E4） | 1, 1.5, 2, 3, 4 |

### 5.3 参照モデルと ID

| 項目 | 値 |
|---|---|
| 参照モデル集合 $R$ | FC-AE、$m_{\mathrm{ref}} \in \{\mathrm{round}(4\hat d_0),\ \mathrm{round}(8\hat d_0),\ \mathrm{round}(16\hat d_0)\}$（$\hat d_0$ は入力空間の TwoNN 推定値）、各 3 seeds。**参照 AE は候補ではないので候補グリッドに丸めない** |
| 主推定器 | **TwoNN**。補助に MLE（$k=10$） |
| 推定用標本 | **train** から固定乱数で 10000 点。**同じ標本を全方法・全時点で使う** |
| **ID 安定性の基準** | 3 つの $m_{\mathrm{ref}}$ にわたる $\hat d_{\mathrm{ID}}$ の**相対範囲**（$(\max-\min)/\mathrm{median}$）が **15% 以内** |
| **判定を適用する表現** | **参照 AE の潜在表現**に対して適用する。入力空間の推定値 $\hat d_0$ は $m_{\mathrm{ref}}$ を決めるためだけに使い、`ID_UNRELIABLE` の判定には使わない |
| **推定器一致の基準** | $\lvert \hat d_{\mathrm{TwoNN}} - \hat d_{\mathrm{MLE}}\rvert / \hat d_{\mathrm{TwoNN}} \le 0.25$ |
| 不一致時 | `ID_UNRELIABLE` を返し、事前宣言した通常の validation 探索（B4）へ切り替える。**切り替えの費用を全額計上し、結果を fallback と明示する** |
| 丸め | $\hat d_{\mathrm{ID}}$ は小数のまま保持し、グリッド点への丸めのときだけ整数化する |

Costa–Hero の MST 由来推定器は**実装しない**。方針 §5.5 E3 のとおり、E7・直接比較・参照依存の評価を先に完了する。

## 10. 事前登録した予測（結果を見る前に記録する）

以下は**外れてもよい**。外れた場合に方針 §11 の該当行へ進むためのものである。

1. A1 を修正すると、AU の $m$ 依存性は現行より**弱くなる**。
2. MNIST 開発条件で $\epsilon_D$ 主水準（10%）を適用すると、選択される $m$ は現行原稿の報告より**大きくなる**。
3. H1（$\mathrm{SD}(300) < \mathrm{SD}(5)$）は、退化条件を除くと**支持されるか判定不能のいずれか**になる。
4. $\Delta\mathrm{AUROC}$ の 95% 区間は $0$ を**含む可能性が高い**。その場合 AU は補助分析へ移す。
5. 「最大 82% 削減」は共通 $Q$ と全費用計上のもとでは**再現しない**。
6. 主設定 $\beta=1$ の MNIST 開発条件では AU $\approx 6 < \hat d_{\mathrm{ID}} \approx 10$ となり、
   **V2 の下側条件が開発条件そのもので不成立になる**見込みである。
   その場合、V2 下側係数の現行値は開発条件に由来する根拠を失うため、規則自体を書き直す。
7. 修正規約では AU の $m$ 依存性がほぼ消えるため、**AU を「容量に応じた有効次元の指標」として提示する枠組みは維持できない**見込みである。
   AU は「$\beta$ が定める遮断水準の指標」として位置づけ直す必要が生じうる。
